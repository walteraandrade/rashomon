# rashomon

Which words stick to a Brazilian political figure, across Bluesky, Google News, GDELT and RSS. Node + TypeScript, Hono API, PGlite database, native ES-module front-end in `public/` with no build step.

## Commands

- `pnpm typecheck` runs `tsc`. `pnpm test` runs `node --test` against an in-memory database. Both must pass before a PR.
- `pnpm build` bundles and minifies `src/ui/app.ts` and its imports into `public/bundle.js` with esbuild. Run it and commit the result whenever a module under `src/ui` changes; `test/bundle-freshness.test.ts` fails if you forget.
- `pnpm dev` serves the API and `public/` on `PORT` (default 3210). `pnpm ingest [source...]` collects. `pnpm reindex` recomputes terms and person matches from stored docs. Both end by rebuilding the graph aggregates; `pnpm aggregate` rebuilds them alone (after a `pnpm push`, for instance). `pnpm warm` asks the deployed site for the page's default recortes.
- `DATA_DIR` selects the PGlite directory (default `./data/pg`). `memory://` is an in-memory database and is what tests use.
- `DATABASE_URL` (or `POSTGRES_URL`) switches every command to a managed Postgres over `@effect/sql-pg`; that is how Vercel runs it (`api/index.ts`, `vercel.json`). `src/push.ts`'s one-shot copy still opens its own `pg.Pool`. `pnpm migrate` creates the schema there, `pnpm push` copies a local PGlite into it. Tests never set it.

## Hard constraints

- PGlite allows one process per data directory. Never run the server and an ingest/reindex on the same `DATA_DIR` at once. Agents working in parallel must each use their own `DATA_DIR`.
- Do not hit external APIs from tests. Collectors are integration code; test extraction and SQL against the fixture in `test/fixture.ts`.
- `seed.json` is the list of tracked people. Aliases match as whole words, case- and accent-insensitive. A one-word alias like "Leite" matches the beverage; prefer full names for common words. Alias words are excluded from the person's own terms. Longer aliases win: "Flávio Bolsonaro" tags Flávio only, never Jair's bare "Bolsonaro". A person's optional `exclude` list holds names that must not feed a bare alias ("Ciro Nogueira" for Ciro Gomes). Run `pnpm reindex` after editing it.
- A `phrase` term is several words as one: a capitalized run (`Alexandre de Moraes`) or a collocation the corpus shows sticking together (`primeiro turno`). The collocation lexicon lives in `phrases` and is rebuilt only by `pnpm reindex`, which therefore reads the corpus twice; `pnpm ingest` loads that lexicon and never adds to it. A phrase replaces the word occurrences it covers, positionally: a word only leaves a doc when every occurrence of it there is inside a phrase, so a word's count means "docs where it appears at least once outside every phrase". A pair touching a tracked person's alias word never enters the lexicon, or a phrase the name filter hides would delete its words with nothing in their place. A phrase carrying one of a person's own name words is dropped from that person's graph.
- `kind` on `/graph`, `/docs`, `/rising`, `/timeline` and `/week` takes a comma-separated list, like `source`. `public/atlas.html` sends `word,hashtag,phrase` (`ATLAS_KINDS` in `api.ts`), the full set: GDELT's theme codes are no longer collected or served.
- Tone exists only on GDELT (`gkg`, `gdelt`) docs. Every other source has `tone = null`. Never invent tone for them.
- `sort=pmi` orders by `pmi * ln(1 + count)`, on purpose, so rare terms do not dominate. Do not change without a test.
- Bluesky blocks unauthenticated bursts. Keep the pacing in `src/collectors/bluesky.ts`; login via `BSKY_HANDLE` and `BSKY_APP_PASSWORD` is the sanctioned path. Never write credentials to the repo.

## Layout

- `src/types.ts`'s `Collector = (persons) => Effect.Effect<RawDoc[], CollectorError, HttpClient.HttpClient | SqlClient.SqlClient>`; `collectors/index.ts` registers each module's own `collect` Effect directly, and no collector module exports a Promise-returning wrapper around it. `CollectorError` is an explicit union of `http.ts`'s shared errors plus each collector's own tagged class (`BlueskyError`, `GkgError`, `RssError`; gdelt/camara/senado's `collect` never lets a failure escape, typed as `never`) — a new collector error type is added here by hand, never inferred.
- `src/http.ts` is the collector layer's HTTP boundary (Effect 4 RC, `effect@4.0.0-rc.117`, pinned exact because the RC still renames APIs between builds; `node_modules/effect/AGENTS.md` and `node_modules/effect/ai-docs/` are the reference for this RC's own API, read them before writing or changing Effect code here): `getBytes` is one capped, timed GET on Effect's `HttpClient` (`limit`/`timeoutMs` default to `MAX_RESPONSE_BYTES`/`REQUEST_TIMEOUT_MS`, the byte cap and the wall-clock cap always travelling together), `fetchClient` the only layer (global fetch, trace-header propagation off); nothing in `src/` turns a collector Effect into a Promise any more, `ingest.ts` provides the layers at its own entrypoint. `gkg.ts`'s zip download carries its own ceiling, `GKG_DOWNLOAD_TIMEOUT_MS` (300 000 ms), passed as `getBytes`'s third argument, distinct from every other collector's default `REQUEST_TIMEOUT_MS` (45 s) — a slot is too large for the ceiling sized for small JSON endpoints; a per-slot failure (oversize or a timeout) is caught inside `collect` so it costs only that slot, never the run. `camara` and `gdelt` keep their hand-measured retry counts and backoff formulas, now as typed, TestClock-driven Effects rather than recursive `setTimeout`-free Promises. Tests drive every collector through `test/effect.ts`: a stub `fetch` handed to `FetchHttpClient.Fetch`, `TestClock` for every pause and timeout, `TestConsole` for the log lines, so a 45 s timeout or a 5-minute download costs the suite nothing.
- `src/ingest.ts`'s `ingest(persons, names, options)` is the orchestration Effect: `migrate`, `pruneRemoved`, `upsertPersons`, `loadPhrases`, `docCount`, `analyzeAfterWrite`, `buildGraphAggregates` and `analyzeTables` are every call whose failure fails the whole run, each as a typed `IngestFailure({ stage })`. Every stage but `buildGraphAggregates` (still `Effect.tryPromise`, out of scope so far) runs as a native Effect `yield*`, mapped with `Effect.mapError` into that `IngestFailure` — none of them goes through `Effect.promise`/`Effect.tryPromise`, so a rejection can never resume as a `die` that bypasses a caller's `Effect.catchTag`. A collector's failure or an unknown source name costs that source alone (`Effect.exit`, logged, `docs = []`), and `insertDocs` (never rejects by construction, `Effect.orDie` enforcing it) still runs for it. `IngestOptions` holds only `collectors`, overriding the real registry per source; a stage failure is reached only through the ambient `SqlClient.SqlClient`, which `test/ingest.test.ts` makes fail with `test/effect.ts`'s `failingSql(client, match)`, a proxy over the real client that fails only the one statement `match` recognizes — never a per-stage option. `Effect.forEach(names, …, { concurrency: 1 })` keeps sources sequential, Bluesky-last order intact. The CLI entrypoint provides `HttpClient` (`fetchClient`) and `SqlClient` (`db.ts`'s own running connection, fetched once via `runSql(SqlClient.SqlClient)` — never a second one on the same `DATA_DIR`) and sets `process.exitCode = 1`, never `process.exit()`, on a failed run.
- `src/extract.ts` normalization, hashtags, words, phrases, stopwords, person matching.
- `src/phrases.ts` the collocation lexicon: staging every adjacent word pair, the count/stickiness floors, loading it back. `loadPhrases` is Effect-native (`SqlClient.SqlClient`, `SqlError`); `loadPhrasesP` is its `runSql(...)` adapter. `buildPhrases`, `stagePhrases`, `resetPhraseStage` stay Promise-only, `reindex.ts`'s own.
- `src/db.ts` picks the `SqlClient` layer by `DATABASE_URL`/`POSTGRES_URL` (`@effect/sql-pg` when set, `@effect/sql-pglite` at `DATA_DIR` otherwise; `memory://` for tests) and wraps it in the `db: { query, exec, close }` Promise adapter every other module calls. `migrate`, `analyzeTables`, `analyzeAfterWrite` and `docCount` are Effect-native, requiring `SqlClient.SqlClient` and failing with `SqlError`; `migrateP`, `analyzeTablesP`, `analyzeAfterWriteP` are their one-line `runSql(...)` Promise adapters (`docCount` has none — `ingest.ts` is its only caller). `poolConfig` stays pure/synchronous and, besides `@effect/sql-pg`'s own `PgPoolConfig` fields, still returns `pg`'s `connectionString`/`connectionTimeoutMillis` so `src/push.ts`'s own `pg.Pool` keeps working unchanged. `runInTransaction` (re-exported by `store.ts` as `inTransaction`) is the only way a transaction opens: always through `inTransaction` at a Promise call site or `sql.withTransaction` at an Effect one, never a raw `begin`/`commit`/`rollback` string; a nested `inTransaction` becomes a savepoint. `runSql` opens none — it is the Effect-to-Promise runner every `P`-suffixed adapter goes through, joining whatever transaction (if any) is already open. A module-private `AsyncLocalStorage` (shared with `store.ts`) is what lets a plain `db.query`/`db.exec` call made inside an open `inTransaction` join it. Under `PERF=1`, `DbLayer` itself wraps the resolved `SqlClient`'s `unsafe` to time and count every statement — the one point every write, whether through `db.query`/`db.exec` or a bare Effect writer's own `sql.unsafe`, passes through — so `db`'s own `query`/`exec` are never separately wrapped (that would double-count).
- `src/store.ts` inserts docs and persons (shared by ingest and reindex); each writer (`pruneRemoved`, `upsertPersons`, `writeDerived`, `insertDoc`, `insertDocs`) has one Effect implementation, requiring `SqlClient.SqlClient` and failing with `SqlError` under its bare name, so a caller can `Effect.catchTag` a typed `SqlError` instead of catching a flattened Promise rejection; a caller outside the Effect world (`reindex.ts`, `score.ts`, `server.ts`, `test/fixture.ts`, …) imports the one-line `P`-suffixed Promise adapter (`runSql(<name>(...))`) instead.
- `src/aggregate.ts` builds `graph_scopes` and `graph_terms`: per window (`query.ts`'s `DAYS`) and single source (its `SOURCES` + `all`), the counts `graphFastQuery` reads by primary key so the `/graph` statement never scans the corpus on a MISS; `graph_terms` holds not every term but, per `(source, kind)`, the top `TOP` (`LIMITS`' largest) of each ordering the route can request — by count, and by `pmi * ln(1 + count)` once per `min` in `MINS` — plus the signature's five, so every `sort`/`min`/`kind`/`limit` still reads exactly the live answer while the table stops growing with the corpus (the full list reached 544 MB and filled the production disk); `links` and `testimony=1` still run live. The PMI denominator lives in `graph_terms_all`, a `create temp table ... on commit drop` built once per window inside that window's own transaction (issue #203) — never a persisted table, so it costs no disk and needs no `analyze`. `pnpm aggregate` runs it (`--if-missing` skips a database that already has a build); `pnpm ingest` and `pnpm reindex` call it last and analyze the two persisted tables (the builder itself never analyzes). One transaction per window; scopes and terms come from the same person list, so a scope row always has its terms. `graphFor` tries the fast query when `precomputable(q)` (a window in `DAYS`, no domain, no lean, one source) and falls back to the live statement on zero rows; `test/aggregate.test.ts` pins that both render identical output on every recorte of the fixture and that only the window edge (build time, not request time) tells them apart. A change to `graphQuery`'s counting rules is a change to `aggregate.ts` too. The pmi ordering, the signature floor and the own-name filter both files share live in `src/scoring.ts`, not repeated here or in `graph.ts`.
- `src/scoring.ts` the four scoring fragments `graph.ts` and `aggregate.ts` both build SQL around: `pmiRank` (`pmi * ln(1 + count)`), `sortKey` (branches on `sort=pmi` between `pmiRank` and the bare count), `signatureFloor` (`greatest(3, about * 0.05)`) and `isName` (a term is, or a phrase carries, one of a person's own name words — subsumes the old `namePhrase`). Pure `Sql`-returning functions built only with `sql.ts`'s tag; imports nothing from `graph.ts` or `aggregate.ts`, so both import it and neither cycles back.
- `src/warm.ts` asks the deployed site for the page's own recortes (`warmPaths`, built with `src/ui/api.ts`'s functions so the cache key matches) after every ingest and every production deploy. No network in tests: `warm` takes its `fetch`.
- `src/sql.ts` the `sql` tagged template: an interpolated value becomes the next `$N`, an interpolated fragment is spliced with its binds renumbered, `sql.raw` for identifiers, `sql.join` for lists. A value or fragment used twice is bound twice, so cast where Postgres needs a type from context (`${days}::int + ${baseline}::int`). Never hand-number a placeholder.
- `src/graph.ts` scoring SQL: counts, PMI, term-term links, sources. Every statement is a builder `(person, q, …) => Sql` built with the tag; `queries` exports the builders for `pnpm bench` and `statements` the text a sample call renders, which is the route's text because numbering follows shape, not values (`test/graph.test.ts`).
- `src/server.ts` Hono routes + static files.
- `src/query.ts` query parsers for every route; each integer parameter snaps onto a short list there (`DAYS`, `LIMITS`, `MINS`, `BASELINES`, `OFFSETS`), so the cache surface stays bounded.
- `public/atlas.html` is the current UI, served at `/`. It is markup only: the Google Fonts link, one `<link rel="stylesheet" href="atlas.css">` and one `<script type="module" src="./bundle.js">` (the built artifact; the source is TypeScript under `src/ui`, which every test imports and which `public/` never ships -- a browser cannot run it, so the bundle is the only script the page loads). No `<style>` block, no inline script, no inline `style=` except a `--var` override for a genuinely dynamic value. Each figure carries its own sentence inside its `.figure-head` (`.sentence-line`, its own `<select>`s) and a `.figure-key` that names the encoding (tamanho, cor, posição, clique) so the graph teaches itself. The page-wide `#stats` badge is now `#atlasStats` inside `#workspace`. Below it the page is a sequence of five `.figure` cards, one per graph, each with a numbered eyebrow, a title, a short subtitle, the key and its own toolbar: `#workspace` (the radial atlas, its toolbar and the `#inspector` detail column), `#testimony` (the outlet beeswarm strip, then the recorte's own number with the per-source means as chips, then one merged outlet list in `#outletList` — `/sources`' document counts and `/testimony`'s means on the same row, laid out in as many columns as the figure is wide), `#compare` (the ruler comparing two tracked people: the shared or exclusive word itself written on the axis, in the same language figure 1 speaks, positioned by which side it leans toward and set in a type size earned by documents on both sides combined, with its own detail line in `#compareDetail`, a note in `#compareHiddenNote` for the own-name words it drops and a `.ruler-overflow` list, inside `#compareRuler`, naming and counting the words the strip could not hold without overlapping) and `#rising` (a second ruler, one person against her own past: `GET /rising`'s `days`/`baseline`/`kind`/`limit`/`min` stay fixed at 7/30/`word,hashtag,phrase`/40/3 — not exposed as controls, only `person` and `source` are — the ruler holds the route's `present`, the 40 most present words of the week (`terms`, the highest lifts, is one tail and lands on one side of any ruler), each positioned by its share of everything written about the person, `balance = clamp(log2((count_recent_raw ÷ about.words_recent) ÷ ((count_baseline_raw + 1) ÷ about.words_baseline)) / 3, -1, 1)` (`shareBalance` in `render.ts`; shares, not doc counts, because a corpus whose docs grow longer inflates every word's lift at once), "antes (30 dias)"/"agora (7 dias)" on the same `--cmp-a`/`--cmp-b` ends `#compare` uses, the first `RARE_SHOWN` (12) of `rareRisers` (`terms` minus `present`, `lift > 1`, saying "12 de N" when it cuts) as a `.ruler-rare` button list after the overflow, and the person's own window totals, `about.recent`/`about.baseline` plus `about.words_recent`/`about.words_baseline` as "pares texto-palavra", spelled out in `#risingAbout` since the relative axis alone hides that story; a payload cached before `present`/`words_*` existed fails `hasShares` and paints by the older person-lift rule, `liftOfPerson`/`liftBalance`, with that rule's axis prose and no list, never a NaN) and `#week` (seven columns of words, one per Brazilian calendar day, oldest left, from `GET /week` at a fixed `days=7`: the mark is the word, its size the day's document count on one ramp for the whole week whose ceiling the column width sets, `--ink` only; `about` sits beside each day label as a `.stat`; a word wider than its column goes to that column's `.week-overflow` list; the svg is drawn at the column's measured width, never scaled, and under 700px `atlas.css` stacks the seven days; a click opens `#docsDialog` for that person, term and calendar day (`day=`), the kicker naming the day). There is no side column, no candidates panel and no page-wide outlet filter: clicking an outlet in `#testimony` focuses it inside that figure only — a repaint of that figure plus its own `/docs` request for the card, never a change to figure 1, and `api.ts` sends `domain` on `/docs` alone — and clicking it again or clicking empty space in the figure releases it and closes the card; the ruler's own click-to-select works the same way, inside `#compare` (or `#rising`) only. Documents open only in `#docsDialog`, and only on a deliberate click, one per figure: in `#workspace` picking a word asks for that word's texts and the person's own two entry points — the centre of the map (`.center-label`, `data-person-docs`) and the head of the list (`.column-person`) — ask for hers; in `#testimony` focusing an outlet asks for that outlet's texts (`domain=`, no term); in `#compare` picking a word asks both people at once, two labelled columns in one card (`.docs-columns`, `.is-wide`), because a word on that ruler is never one person's; in `#rising` picking a word asks the one tracked person, for the recent 7-day window only, never the 30-day baseline the figure also scores against. The inspector carries no button, and releasing any of those selections closes the card. On a viewport at least 760px wide the dialog is opened with `.show()` and floats (`.is-floating`, `position: fixed`, dragged by `#docsGrip`), so the figure stays readable and the card survives the next pick; narrower than that it falls back to `.showModal()`. Nothing on the page GETs `/docs` on its own. `#helpDialog` is the in-page guide: `src/ui/help.ts` intercepts clicks on `como-ler.html` (header and each figure's "Como ler") and opens it at the matching section, so the reader never has to leave the graph. Modifier-click, `target=_blank` and `data-leave` still go to the page. `public/como-ler.html` is the shareable copy of that same guide (frequência, PMI, PMI × ln(1 + documentos), lines, tone, phrases, the kikori avaliação, the ruler, the docs card, the two atlas entry points, overflow and own-name words dropped, in plain pt-BR, `#atlas` `#avaliacao` `#comparar` `#pmi` `#em-alta` `#semana`). Keep both in sync with `src/graph.ts` when scoring changes.
- Every landing page (`atlas.html`, `como-ler.html`, `sobre.html`) ends with one `<script defer src="/_vercel/insights/script.js"></script>` right before `</body>`: Vercel Web Analytics. It is the single exception to the "no external script" rules on those pages — the host serves it, this repo ships no code for it and never bundles it. `test/pages.ts` holds the tag and `test/analytics-acceptance.test.ts` pins it. It only resolves on a Vercel deployment; locally the path 404s.
- `public/atlas.css` holds every rule for every page: `:root` tokens (IBM Plex Sans Condensed for display, IBM Plex Sans for text, IBM Plex Mono for every number, label, chip and word on a figure), layout, components, the figures (including the ruler's `--cmp-a`/`--cmp-b` hue pair and the evaluation `--hostile`/`--favor` pair), the two dialogs and the reading page. `public/como-ler.html` links it too. No page gets a `<style>` block.
- The site draws one border, `1px solid --line` with 2px corners, on every figure, chip and dialog alike; inside a figure type and space carry every limit, and the page behind the figures is a 16px dot grid. Colour is a second hierarchy and it means something: `--ink` is "read this", `--accent` (amber) is the live control and the `//` marker before every eyebrow, `--hostile`/`--favor` are evaluation, `--cmp-a`/`--cmp-b` are who, `--muted` is support. A heading that needed colour to be found is a heading in the wrong place. One ramp, `--t-mega … --t-micro`, is the only source of size: a rule writes `font-size: var(--t-*)`, never a px literal (`test/leitura-ui-acceptance.test.ts` fails on a loose `font-size: …px`, and `--t-micro`, 11px, is the floor and belongs to SVG labels only). Each element has exactly one style: `h1` names the page and appears once, in the `.masthead`; `h2` names a section (a figure, a chapter of `como-ler.html`, a dialog title); `h3` names a block inside one (a topic, the inspector's selected term); `.eyebrow` is the small mono label, after a `//`, that names whatever sits under it, and space above a heading is its rank. Headings are the condensed display face in capitals; rank is weight, case and family as much as size. `dt`/`dd` is the site's label-and-number pair: the default is a real definition list (term in display, meaning in sans — `.pmi-scale`), `.stat` inverts it so the measurement leads, and `.figure-key` is the compact encoding on each figure (name in eyebrow type, meaning in sans).
- `src/ui/format.ts` pure formatting, labels and URL helpers, plus the shared exported types (`Term`, `Link`, `Graph`, `Layout`, `Measure`, `Compare`, `CompareTerm`, …) the other modules import. `mergeOutlets` joins the two outlet payloads into the second figure's single list; `balanceColor` is the ruler's own red/grey-analogue two-hue ramp. Markup is built only with its `html` tag: every interpolation is escaped unless it is already an `Html` value (arrays join, null/undefined vanish), `raw()` vouches for markup built elsewhere, and `esc` is private. A template literal that looks like markup must carry the tag and nothing may feed `innerHTML` a bare backtick literal (`test/invariants.test.ts` scans every module for both). The tag escapes values, not structure: attribute quotes are still hand-written, and `safeHref`/`safeDocUrl` still validate URL schemes, which escaping never does.
- `src/ui/api.ts` URL building and fetching for the documented routes (`/graph`, `/sources`, `/docs`, `/testimony`, `/candidates`, `/compare`, `/rising`, `/week`, `/timeline`). No DOM.
- `src/ui/layout.ts` pure geometry: `wrapLines`, `centerLabel`, `packPass`, `pack`, `routeGraph`, `routesFrom`, `swarmBy`, `swarm`, `rulerLayout`, `weekLayout`. `swarmBy` is the one beeswarm skeleton both strips share (sort by size, take the y nearest the axis that clears everything placed); `swarm` is it with circle clearance for figure 2 and for figure 1's strip mode (`termStripLayout` in `render.ts`), and `rulerLayout` is it with box clearance for a ruler's words, which is why there is no second packer — figure 3 and figure 4 both feed it the same `RulerItem[]` shape (`term`, `kind`, `balance`, `combined`) and neither needed a change here; `weekLayout` is one `swarmBy` per day column with box clearance and the ruler's overflow contract, sized on one week-wide ramp (`WEEK_SIZE_MIN`…30px, the ruler's ceiling). No DOM — text metrics arrive as an injected `measure(text, size, family, weight)`, which `render.ts`'s `createCanvasMeasure()` supplies in the browser and a stub supplies in tests.

Nothing here reaches into figure 1's, figure 2's or figure 4's DOM, and none of them reach into this one. Exports `mount`.
- `src/ui/figures/rising.ts` owns figure 4 end to end: its own sentence (person, source only — `days`/`baseline`/`kind`/`limit`/`min` are sent explicitly at the route's own fixed values, never selectable), `GET /api/people/:id/rising`, opening `#docsDialog` with one side, the tracked person, scoped to the last 7 days regardless of the figure's own 30-day baseline. Wires `figure.ts`'s `runFigure` (`name: 'rising'`, `el: #risingRuler`). Nothing here reaches into any other figure's DOM, and none of them reach into this one. Exports `mount`.
- `src/ui/figures/week.ts` owns figure 5 end to end: its own sentence (person, source, limit — `days` is always 7, never a control), `GET /api/people/:id/week`, opening `#docsDialog` with one side and `day=` for that column, the column width measured from one `.week-day`. Wires `figure.ts`'s `runFigure` (`name: 'week'`, `el: #weekChart`, `markSelector: '[data-term]'`) for load/abort/ghost, the background-click/Escape release, and the resize repaint — no second `ResizeObserver` of its own: the runtime's calls this figure's own `paint` again, whose own `repaint()` already remeasures the column and repaints twice. Its own `paint` only clears `selected` on a genuinely new dataset (`result !== data`), never on that resize-driven repaint, which calls `paint` with the same object again. Nothing here reaches into any other figure's DOM. Exports `mount`.
- `src/ui/docs-card.ts` owns `#docsDialog` and is the only path to `GET /docs`. It belongs to no figure — all five open it — so `app.ts` wires it once with `mountDocsCard()` and each figure calls `open({ kicker, title, sides, owner })` with its own recorte: one side for a word, a person, an outlet or a calendar day, two for the compare ruler, never two for the rising ruler since a rising word is one person's. It also owns the floating/modal split (`FLOATING_MIN`, 760px), the drag by `#docsGrip`, the memo per side and the abort. `openedBy(owner)` says whether the open card is that figure's, which is how a figure releases its own pick without shutting a card another figure opened over it. Exports `open`, `close`, `isOpen`, `openedBy`, `mountDocsCard`.
- `src/ui/figure.ts` owns the abort/stale/scope/ghost/background-click/Escape/resize skeleton `compare.ts`, `rising.ts`, `week.ts` and `testimony.ts` all wire through, so a sixth figure needs only its own `params`/`fetch`/`paint`. Sits between `docs-card.ts` and `figures/*.ts` in the import order (imports `docs-card.js` for `openedBy`/`close`, never the reverse). `runFigure(opts)` returns `{ load, reload, repaint, release }`: `load()` tracks its own `requestId`/`AbortController`, ghosts only on a real `readScope` miss (against `opts.scope`, which defaults to `opts.name` — `testimony.ts`'s `outlets` instance sets it apart, to `'sources'`, so a memo hit records the route it actually hit, not the figure's own name), drops a stale or aborted result silently, and closes a `span('figure:'+name)` on success, merging in `opts.detail?.(data, params)` when given (`{ person, rows }` for outlets, `{ person }` for testimony/rising/week, nothing for compare, which speaks for two people at once). A caught, non-aborted error resets `hasData`/`lastData` before `paintError`, so a resize afterwards repaints nothing stale. `reload` is a shared `debounce(load)`; `repaint()` re-paints the last successful result with no fetch, but is a no-op between a ghost paint and that fetch settling (`loading`), so a resize during a real fetch never draws over the ghost with the previous result — the tradeoff: a resize during a `reload()` whose own `ghost()` only dimmed the old drawing (`root.classList.add('is-loading')`, most figures' own `ghost()`, rather than replacing it) does not repaint at the new width either, until that fetch settles; `release()` calls `onRelease` and then `docsCard.close()` only `if (docsCard.openedBy(name))`. Passing `el` (one element or several) wires a click listener that calls `release()` unless the target matches `markSelector`, a `document` `keydown` listener that releases on Escape, and a `ResizeObserver` on `el[0]` that calls `repaint()` only when its `clientWidth` is non-zero and has actually changed since the last callback, and never refetches; omitting `el` opts out of all three, for a figure with its own richer resize handling. `figures/atlas.ts` does not adopt it — three independent fetch flows, two `ResizeObserver`s and a mode/zoom state machine the shared shape does not fit — and keeps its own loop.
- `src/ui/help.ts` owns `#helpDialog`. It belongs to no figure. `app.ts` wires it once with `mountHelp()`. Clicks on `como-ler.html` open the dialog at the hash; the module does not fetch and does not paint. Exports `mountHelp`, `openHelp`, `closeHelp`.
- `src/ui/app.ts` is a shell: it fetches `/api/people` once, seeds each figure from bare and prefixed querystring keys (documented in `docs/operations.md`, "Front-end bootstrapping"), mounts the docs card and the help dialog, and calls each figure's own `mount()`. A failed `/api/people` travels down to every figure as `peopleError`, so an outage reads as an outage and never as an empty `seed.json`. Its only export is `boot`; `boot()` runs only when a `document` exists, which is what lets tests import the wiring.
- `src/ui/perf.ts` User Timing marks: `span(name)` returns a closer that records one `performance.measure` and never throws, `memoHit(route, key)` records the `api:<route>` pair on a `fromScope` hit, `routeOf(url)` names the route. `api.ts` marks every finished call (`api:<route>`, failures included, aborts excluded) and each figure marks request-to-paint (`figure:<name>`). No DOM; this repo never posts the entries. `docs/operations.md`, "Measuring it", says how to read them by `detail.cache`.
- `README.md` is the short landing page: what the project is, quick start, commands, the four honesty caveats, links. The reference lives in `docs/`: `api.md` (routes), `sources.md` (collectors and `seed.json`), `terms.md` (PMI, phrases, candidates, lean, tone), `testimony.md` (kikori), `operations.md` (env, deploy, writes, indexes, benchmarks, caching). A change documents itself in the matching page, not by growing the README back: a layout or constraint every agent must know goes in `CLAUDE.md`, a change to the factory pipeline itself in `docs/factory.md`. `DESIGN.md` and `PRODUCT.md` at the repo root are the visual and product spec (impeccable); they are not the `docs/` reference.
- Import direction is one way and acyclic: `format.ts` ← `layout.ts`, `marks.ts` ← `render.ts` ← `docs-card.ts` ← `figure.ts` ← `figures/*.ts` ← `app.ts`, with `api.ts`, `state.ts`, `perf.ts` and `help.ts` at the bottom (`state.ts` imports `perf.ts` for the memo-hit mark; `app.ts` also imports `api.ts`, `docs-card.ts`, `help.ts` and `render.ts` directly, to load the people, mount the card and the guide and paint the boot ghosts). `compare.ts`, `rising.ts`, `week.ts` and `testimony.ts` import `figure.ts` but no longer `perf.ts`/`state.ts` directly — the span and the scope/debounce calls live inside `figure.ts` now; `figures/atlas.ts` keeps its direct `perf.ts`/`state.ts` imports, unchanged. `test/invariants.test.ts` enforces it.
- The front end is TypeScript like the rest of `src/`, so `pnpm typecheck` covers `src/ui` with no `allowJs`/`checkJs` escape hatch. Modules import each other with `.js` specifiers (`./format.js` resolves to `format.ts`), which is what NodeNext, tsx and esbuild all agree on. A new module or parameter needs its types, or `tsc` fails.
- `test/` node:test suites. `test/fixture.ts` seeds two people and six docs; extend it rather than creating ad-hoc data. `test/fake-dom.ts` is a minimal `document` stand-in for asserting the markup `render.js` emits. A test asserts on output or behaviour; a test may read a module's source only to check a repo-wide invariant listed in `test/invariants.test.ts`, never to check that one function calls another.
- Front-end behaviour is tested by importing the modules, never by grepping `atlas.html` for JavaScript. A criterion about a click or keystroke goes through `createHandlers`; a criterion about markup goes through the painter that emits it.

## Style

- Code, comments, commits, branches, PR titles in English. UI copy in pt-BR.
- Functional style, small pure functions, no classes, except in exactly two shapes: a `Data.TaggedError` (a typed failure, e.g. `ResponseTooLarge`, `BlueskyError`) and a `Context.Service` (an Effect service definition). Nowhere else. Comments only when the why is not obvious.
- A comment states the constraint; history lives in git and docs/.
- Commit messages short and imperative. Branch names `feat/ | fix/ | chore/ | refactor/ | docs/ | test/` + short kebab slug.
- Keep the API contract stable: `GET /api/people`, `GET /api/people/:id/graph`, `GET /api/people/:id/sources`. New capabilities are new routes or new optional query parameters, never breaking changes to existing fields. `testimony=1` on `/graph` is one such parameter: off, the response is unchanged.

## Factory

Feature work goes through the pipeline in `docs/factory.md`: `spec` workflow → human adds `spec-approved` → `build` workflow → PR → human review. Roles live in `.claude/agents/`; whoever builds never validates. Builders work in `../rashomon-<slug>` worktrees, never on the main checkout.
